## Revision — 2026-08-31 — same day, following the FAIL verdict
Two design decisions needed the player's call, both resolved: (1) a **per-visit spend cap** (1 purchase per Sanctuary visit, drawing from any archetype or overflow) — this is what finally makes "which path first" a real, binding choice, since only one purchasable node can be taken per visit regardless of how much is banked elsewhere; (2) **overflow points** — once an archetype's chain is fully spent, further mastery of it converts to a wildcard point spendable on any other archetype's locked node, keeping Tower Mastery's positioning wager meaningful for the entire playthrough instead of going dead once a chain completes.

All mechanical fixes applied in the same pass: the double-grant bug closed by giving Hero Skill Tree sole ownership of the `skill_tree_points` mutation (Tower Mastery now emits unconditionally, forever, with zero cross-system reads — the `all_nodes_unlocked()` direct call was removed entirely); the save schema corrected to 16 nodes; the uncatalogued-signature income question resolved (the global `MASTERY_UNLOCK_THRESHOLD` fallback applies to every build signature, not just the 8 catalogued ones); a new `skill_tree_overflow_point_earned` event added to `event-bus.md`. Companion fixes landed the same day in `tower-mastery.md` (Rule 7/12 contradiction, stale references, Player Fantasy rewrite), `hero-skill-build.md` (Rules 14-17 corrected to attribute `skill_unlocked` to Hero Skill Tree), `sanctuary-ui.md` (new Core Rule 11, a 7th tab-strip entry giving this system its first real Sanctuary mount point), `mission-hud.md` (new Group 11, a real notification rule for the two new events), and `save-persistence.md` (schema/count corrections).
