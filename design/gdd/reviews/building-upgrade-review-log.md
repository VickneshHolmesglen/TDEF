Summary: First review of this GDD (implementation predates review by one day, 2026-08-11 — code + tests already existed and passed). Four of five blocking findings converged on one underlying gap: the GDD's Player Fantasy promises the sanctuary telling the player "unprompted" that an upgrade opened up, but the original doc specified zero delivery mechanism — no per-requirement legibility once an entry is already visible, no signal on the VISIBLE_LOCKED→PURCHASABLE transition, no purchase-confirmation feedback. Closed by reusing two already-established project conventions rather than inventing new UI/audio design: Sanctuary UI's existing Connection Badge mechanism (`sanctuary-ui.md` Core Rule 2, added as a new Equipment Forge tab trigger) for the "unprompted" signal, and Defense Building's existing "Standard tech-node unlock" chime for the purchase-confirmation beat; per-requirement legibility reuses Crafting's own established per-ingredient checklist convention. Added Rule 1a (chain length capped at 3, matching Formula 1's own tier-multiplier table) and Rule 1b (`BuildingUpgradeResource.validate()`, closing both a same-structure prerequisite-cycle deadlock systems-designer found and the previously-aspirational "should be rejected" validation language). Deleted AC-6 (self-contradictory within the same document — claimed 2 interfaces "don't exist today" while the doc's own Open Questions table, same date, marked both "Resolved 2026-08-11") and folded its content into Dependencies; added AC-6 through AC-13 covering the new rules plus 2 previously-uncovered Edge Cases (malformed requirement ID, shared requirement across upgrades) qa-lead identified. Softened Player Fantasy's "cannot be rushed by playing narrowly" overclaim per economy-designer's finding (a player who deliberately assembles a known combination isn't exploiting the system, but the original text overclaimed what non-consumption guarantees) — creative-director explicitly disagreed with economy-designer's framing of this as a blocker requiring a mechanic (e.g. a dwell-time requirement); resolved as a two-sentence honesty edit instead, preserving non-consumption as "the soul of this design." Fixed 2 stale cross-doc downstream notes (menagerie.md, equipment-forge.md still said the 2 interfaces "do not exist yet"). Added the new `building_upgrade_became_purchasable` EventBus event to `event-bus.md`'s catalogue and wired it into `sanctuary-ui.md`'s Connection Badge Tuning Knob table, mirroring `structure_upgraded`'s own established "late merge" precedent.
Separately: godot-specialist surfaced a live, currently-shipping data-loss bug in Tarot (unrelated to this GDD's own design) while tracing the `"tarot"`-requirement dependency — Tarot only registers with `GSavePersistence` while its one scene-instance (child of `TarotDeckUI.tscn`) is alive, so any save made outside that scene (including all of Sanctuary) silently drops Tarot's entire unlocked-card ledger. This also proved this GDD's own previously-proposed fix direction for the `"tarot"`-requirement gap ("give Tarot a second shell-owned instance in `SanctuaryUI.tscn`") was actively wrong, not just incomplete — it would create two never-simultaneously-alive instances with silent cross-instance resets. Corrected in this GDD's Open Questions table; the real fix (Tarot → true Autoload) is filed as its own item for Tarot's owner, explicitly not fixed here.
