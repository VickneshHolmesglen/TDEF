## Cross-Doc Correction — 2026-07-15 — `/review-all-gdds` found the session #2 confirmation pulse was dead code
`/review-all-gdds`'s cross-system scenario walkthrough traced the boss-lane telegraph chain end-to-end and found that Rule 11e (added in session #2, same day) reset `_boss_telegraph_cell` at `mission_phase_changed → WAVE_ACTIVE` — the same event that starts the wave. Wave Manager Rule 6 guarantees the BOSS `WaveSpawnEntry` is always last in its wave, so its `monster_spawned` event is guaranteed to arrive strictly after that phase transition, never in the same frame. This meant Rule 11d's confirmation-pulse guard (`_boss_telegraph_cell` non-sentinel) could never evaluate true — not a rare race, but a structural impossibility under any legal Wave Manager content. Fixed in the same session that found it: Rule 11e's reset moved to `wave_completed`, which still guarantees the cell can't leak into the next wave's preview cycle (Wave Manager always fires `wave_completed` before the next wave's `wave_preview_available`) while giving Rule 11d's pulse its full WAVE_ACTIVE window to actually fire. The regression AC was rewritten to walk the realistic full ordering (INTERMISSION preview → PRE_WAVE → WAVE_ACTIVE → non-boss spawns → boss spawn) that the bug made impossible to pass.
Prior verdict resolved: Yes — this was a session #2 regression caught the same day by a different review lens (cross-system scenario tracing, not single-document review), consistent with why `/review-all-gdds` exists as a distinct pass from `/design-review`.
