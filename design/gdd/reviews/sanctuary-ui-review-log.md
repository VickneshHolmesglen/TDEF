## Redesign — 2026-07-24 (5th pass, deliberate, not a patch) — Core Rule 10 rebuilt from scratch
Following the 4th pass's explicit freeze directive, this pass rebuilt the Loadout mechanism rather than patching it again, after a break spent on unrelated work (Encyclopedia and Audio System GDDs, both authored and Approved in between).

**The structural change**: Loadout is no longer a bolted-on `OVERVIEW`-content-zone button sharing an ambiguous mechanism with Launch/Depart. It is now the tab strip's own **6th entry** (Core Rule 2), selectable from any state — `OVERVIEW` or any `ROOM_*` — exactly like the other 5 entries, with one behavioral difference: selecting it tears down the active room (if any) and enters `DEPARTING_TO_LOADOUT` instead of mounting a room. This single change dissolves every one of the 4th pass's 7 blocking findings by construction:
- The terminal-latch race is now residual, not load-bearing — Launch/Depart and Loadout are structurally separate widgets requiring different physical inputs, not two handlers racing to claim the same mechanism.
- The tab-strip entry count is now genuinely, consistently 6 everywhere in the document (Core Rule 2, the Interactions table, all relevant ACs) — no more 5-vs-7 self-contradiction.
- The "tail entries... immediately after Overview" incoherent focus-position description is gone entirely — Loadout is just an ordinary tab-strip entry in the tab strip's own existing tracker, no retrofit language needed.
- Reachability from `ROOM_*` states is now an explicit, deliberate design choice (Loadout is a lateral navigation, not a session-ending action like Launch/Depart) rather than an unspecified gap ACs assumed away.
- Player Fantasy now integrates Loadout directly (a new paragraph in the Player Fantasy section), rather than the hand-off existing only in Core Rules with zero narrative acknowledgment.
- The sibling UX spec (`design/ux/sanctuary-ui.md`) still needs its own update to match this redesign — not done in this pass, tracked as immediate follow-up work, not a defect in this GDD.

One pre-existing, independent finding from the 4th pass (Connection Badges don't convey causal attribution, only "something changed") was deliberately left unresolved and tracked as a new Open Question (OQ-7) rather than folded into this redesign — it predates and is orthogonal to the Loadout problem, and fixing it was out of this pass's own scope discipline (redesign the one thing that was actually broken, don't sprawl into adjacent territory while doing it).
Prior verdict resolved: Yes — directly replaces the 4th pass's frozen Core Rule 10, per that pass's own explicit directive to redesign rather than patch.
