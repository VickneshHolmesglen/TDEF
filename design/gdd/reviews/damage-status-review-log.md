## Cross-Doc Correction — 2026-07-15 (same day, second pass) — Leftover `is_siege` References + Lifesteal-on-Kill Structural Bug
`/review-all-gdds` re-run found 2 issues the same-day earlier pass (below) missed.

**(1) 4 more leftover `is_siege` references**: the earlier pass that day removed one `is_siege` reference (Dependencies table, Tower System row) but missed 4 more: the Interactions with Other Systems table's Tower System row, and AC-1/AC-2/AC-3's GIVEN clauses, all of which still specified `is_siege=false` as part of the `tower_attacked` test payload — testing a field that no longer exists on that event. Fixed: all 4 corrected.

**(2) Lifesteal-on-kill was structurally impossible, not just a race condition**: the cross-system scenario walkthrough traced Rule VII's stated purpose ("preserves lifesteal heals on the killing blow of a wave") against Monster System's actual mechanics and found `monster.md` Rule 21f explicitly erased the killing blow's `_pending_absorbed` entry and suppressed `monster_hp_absorbed` for any lethal hit (confirmed by monster.md's own AC-36, which asserted this exact behavior as correct). Since Rule VI's lifesteal resolution is entirely gated on receiving `monster_hp_absorbed`, this meant lifesteal could never heal the hero on a killing blow — 100% of the time, not as a rare race outcome — directly contradicting this GDD's own stated design intent for Rule VII. Root-caused and fixed in `monster.md` (Rule 21f no longer erases the entry; it flushes normally in the same end-of-frame absorbed-flush pass as any other hit). Traced the corrected timing through Monster System's 4-pass `_physics_process` structure (damage pass → BOSS logic → movement pass, which is where `monster_died`/`wave_completed` actually cascade → absorbed flush pass) and confirmed the killing blow's `monster_hp_absorbed` now reliably fires *after* `wave_completed` triggers Rule VII's deferred-clear registration but *within the same physics frame*, resolving before the deferred clear resumes on the next frame — no residual race. Rule VII.2 annotated with this confirmation; no logic change was needed in this document, since the bug lived entirely in `monster.md`.

Prior verdict resolved: No — both were live, unresolved defects as of this pass; the lifesteal bug in particular had existed since Rule VII was authored (well before this session) and was never caught until a full cross-system trace was performed.
