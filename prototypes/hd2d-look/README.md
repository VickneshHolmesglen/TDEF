# HD-2D Look Prototype

**Status:** in progress (first pass, 2026-10-11)

## Hypothesis

The target look in `docs/images/graphics.PNG` (HD-2D: pixel-painted 2D ground
with real 3D grass, trees and props, tilted camera, depth-of-field, warm sun)
can be produced **entirely procedurally** -- no image-generation model -- now
that Codex no longer generates art for this project.

## How to run

Open `prototypes/hd2d-look/hd2d_look.tscn` and press F6 (or run it via the
Godot MCP `run_project` with that scene). Textures come from
`assets/art/hd2d/`, regenerated by:

    python tools/asset-pipeline/hd2d/generate_hd2d_textures.py

then an editor-mode pass (`Godot --headless --editor --path . --quit`) to
import them.

## What it builds

The Gap's real 16x12 lane layout (copied from `the_gap.gd`), at the project's
1 px = 1 world unit scale (`VisualMath.map_to_3d`):

- Ground: one plane, `hd2d_ground.gdshader` picks grass/dirt/flagstone per
  pixel from a 4 px-per-cell lane mask; lookups snap to a 3-unit pixel grid
  and are noise-jittered, so lane edges are ragged and pixel-stepped.
- Grass tufts and flowers: crossed-quad cards in `MultiMeshInstance3D`
  batches, `hd2d_card.gdshader` (alpha scissor, nearest filter, top-only wind
  sway, up-facing normals so cards never go black edge-on). Density follows
  low-frequency noise so tufts gather in patches.
- Trees: cylinder trunk plus 16 billboard leaf-clump quads on a dome.
- Fence posts/rails, ruined pillars and fallen blocks: boxes with triplanar
  pixel textures.
- Warm `DirectionalLight3D` with shadows, SSAO, filmic tonemap, mild 3D glow,
  `CameraAttributesPractical` near+far DoF (tilt-shift feel).

## Findings (first pass)

- Works: the look reads as HD-2D in one procedural pass -- ragged pixel path,
  lit grass patches casting shadows, framing tree line, fence, ruins.
  Screenshot: `hd2d_look_v1.png`.
- No shader compile errors, no runtime errors (Vulkan, RX 6800 XT).
- 3D `Environment` glow is not the forbidden `use_hdr_2d` path (that ban is
  for 2D canvas glow); kept subtle here anyway.
- `look_at()` before `add_child()` errors ("Node not inside tree") -- aim the
  camera after it enters the tree (`look_at_from_position`).
- Hero art imports with `size_limit=768`, so `Sprite3D.pixel_size` must be
  derived from `texture.get_height()`, not the source PNG size.
