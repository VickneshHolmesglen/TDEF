## Automated Tests

**Status**: PASS (re-verified 2026-07-03 after fix) — 299/299 tests passing, 0 errors, 0 failures, across all 24 test suites.

**Original finding (now fixed)**: `tests/unit/tower/tower_placement_test.gd` and `tests/unit/tower/tower_combat_test.gd` used Python-style keyword-argument call syntax (`_make_data(cost = 30)`, `_make_data(weapon_damage = 35.0, ...)`), which GDScript does not support (no named/keyword arguments exist in the language) — this blocked both files from being parsed/loaded at all, meaning their tests had never actually run despite S3-03 being marked Complete. Fixed by converting all 20 call sites to positional arguments matching `_make_data`'s actual signature. Re-run confirms both files now parse and pass: `tower_placement_test.gd` (15 tests), `tower_combat_test.gd` (19 tests).

**New finding during fix (advisory, logged as TD-tower-002)**: Both tower test files leak orphan `Node` instances — `TowerSystem` extends `Node`, but `after_test()` only sets `_ts = null` instead of calling `.free()`, which does nothing for a `Node` (unlike `RefCounted`). 34 orphans reported across the two tower suites. Not blocking — same category as the already-tracked TD-monster-003, logged for follow-up, not fixed in this pass since it wasn't the reported failure.
