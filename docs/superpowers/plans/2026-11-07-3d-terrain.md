# 3D Terrain (Hills + Rivers) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-map generated hills and rivers that change play (hill cost/range, monster-blocking hills, slowing water), drawn as a smooth 3D heightfield under the existing tilted camera.

**Architecture:**
- Terrain facts (`height_level`, `water`) live on `GridConfig` and are mirrored by the `Grid` autoload, so every gameplay rule works headless.
- `TerrainGenerator` fills them after `MapGenerator` walks the path, using the same RNG.
- A presentation-only `TerrainSurface` turns the levels into a smooth height function. `Hd2dScenery` meshes it, towers stand on it, and 2D overlays, picking and the hero sprite use its screen lift.

**Tech Stack:** Godot 4.6.2, typed GDScript, gdUnit4, Godot MCP for live checks.

**Spec:** `docs/superpowers/specs/2026-11-07-3d-terrain-design.md` (approved 2026-11-07)

**Generation rules (the tests below enforce them):**
- **Hills:** grow blobs from random interior PLACEABLE seeds over PLACEABLE cells until the hill share ≈ `hill_coverage`. Never touch PATH, SPAWN or GOAL; touching the lane is allowed.
- **Level 2:** when `max_height_level` is 2, level-2 cells are level-1 cells whose 4 neighbours are all hills.
- **Rivers:** each river is a top-to-bottom meandering band `river_width_cells` wide.
  - It may cross the lane: a PATH cell under a river becomes a ford (water = true).
  - Hills under a river are removed (water forces level 0).
  - Choose the river's columns so it crosses the main lane at least once.
- **Buildable share:** if the buildable share (PLACEABLE, not water) falls below `min_buildable_share`, shrink hills first. Then narrow rivers to 1 cell. Never drop below 1 river if the profile asks for one.

### Task 5: TerrainSurface — smooth height, screen lift, height-aware picking

**Files:**
- Create: `src/presentation/terrain/terrain_surface.gd`
- Test: `tests/unit/visual_presentation/terrain_surface_test.gd`

**Interfaces:**
- Consumes: `GridConfig` (cells, heights, water, cols, rows, cell_size), `TerrainTuning.height_per_level_cells`.
- Produces `class_name TerrainSurface extends RefCounted` with:
  - `static func from_config(config: GridConfig, tuning: TerrainTuning) -> TerrainSurface`. Returns null when `heights` and `water` are both empty (no terrain).
  - `height_at(p2d: Vector2) -> float`: smoothed height in 2D px. Target heights:
    - each cell's level × `height_per_level_cells` × `cell_size`;
    - water cells `-0.15 × cell_size` (river bed);
    - fords `-0.05 × cell_size`.

    Precompute a grid of 8 samples per cell, separable-Gaussian blurred with sigma ≈ 0.45 cell. Then pin PATH, SPAWN and GOAL samples whose distance to a non-path cell is > 0.3 cell back to 0, so the lane is flat. Sample bilinearly; outside the grid, clamp to the edge.
  - `water_level() -> float` = `-0.04 × cell_size`.
  - `screen_lift(p2d: Vector2, pitch_deg: float) -> float` = `height_at(p2d) × cos(pitch)`.
  - `screen_to_ground(screen_p: Vector2, pitch_deg: float) -> Vector2`: the ground point `p` with `p.y − screen_lift(p) == screen_p.y` and `p.x == screen_p.x`. When there are several, take the one with the **largest** `p.y` (front-most toward the camera). Search: march `p.y` from `screen_p.y + max_lift` down to `screen_p.y` in steps of 1/8 cell, then bisect.
