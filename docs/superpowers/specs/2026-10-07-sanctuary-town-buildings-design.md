# Sanctuary Town Buildings (Overview Diorama)

**Date**: 2026-10-07
**Status**: Decisions made by the user in chat (5 tiers; Codex art with placeholders now; per-tab progress score; clicking a building opens its tab). Implemented alongside this spec.
**Scope**: Fill the Sanctuary OVERVIEW diorama with one building per side-panel tab, plus the Castle centerpiece. Each building upgrades passively through 5 visual tiers as that tab's own progress grows. Clicking or selecting a building opens its tab. Art is generated by Codex (queued in `production/art-overhaul-status.md`); until it lands, buildings render as clearly-placeholder shapes that still visibly grow per tier.

## 1. Player Fantasy

The Sanctuary stops being an empty panel and becomes a small town that grows with you. Every system you invest in shows up as a building getting bigger and grander, so the Overview is a glance at how far each part of your sanctuary has come, and a map you can click to go there.

## 2. Buildings

| Building | Tab (target state) | Progress score (0-1) |
|---|---|---|
| Castle | Overview (centerpiece, not clickable to a room) | mean of the six scores below |
| Armoury | Inventory & Crafting (`ROOM_INVENTORY_CRAFTING`) | 0.5 x inventory expansion tier / max tier + 0.5 x crafting recipes discovered / total |
| Menagerie | Menagerie (`ROOM_MENAGERIE`) | 0.5 x min(1, creatures kept / 12) + 0.5 x distinct species kept / total species |
| Keep | Defense Building (`ROOM_DEFENSE_BUILDING`) | (techs unlocked + structures built) / (all techs + all structures) |
| Blacksmith | Forge (`ROOM_EQUIPMENT_FORGE`) | 0.5 x equipment recipes discovered / total + 0.5 x min(1, runes known / 8) (runes are discovered, there is no fixed rune catalogue) |
| Training Hall | Skills (`ROOM_HERO_SKILLS`) | 0.6 x skill-tree nodes unlocked / all nodes + 0.4 x skills learned / all skills |
| Seer's Tower | Loadout (`DEPARTING_TO_LOADOUT`) | 0.6 x tarot cards unlocked / all cards + 0.4 x mean mastery tier of unlocked cards / 4 (the top mastery tier) |

A missing system (e.g. no Crafting instance in a test scene) contributes 0 to its term, never an error. All scores are computed by `SanctuaryProgress` (pure, static), which reads the real systems.

## 3. Tiers

`tier = 1 + floor(score x 5)`, clamped to 1..5: tier 2 at 20%, tier 3 at 40%, tier 4 at 60%, tier 5 at 80%. Tier 1 is the humble starting building every player sees.

## 4. Presentation

- A `Town` layer in the diorama, beneath the existing built-structure layer (watchtower/habitat sprites, shadows and habitat label are unchanged). The old "Castle" text placeholder is replaced by the Castle building.
- Each building is defined by data, `SanctuaryBuildingResource` (`assets/data/sanctuary_buildings/*.tres`): id, name key, target state, position, footprint size, placeholder colour, and 5 tier texture slots.
- **With art:** the tier's texture fills the footprint (aspect-fit, bottom-aligned).
- **Without art (now):** a coloured block whose height grows with the tier (55% to 100% of the footprint), a darker roof band, the building name, and 5 tier pips. Clearly a placeholder, but the growth already reads.
- **Selection:** buttons focusable with keyboard/gamepad, as well as mouse. Hover or focus shows an info line at the bottom of the diorama: name, tier n/5, progress %, and what grows it. (2026-10-07 update: the line sits on a translucent dark chrome strip at 14 px, ending before the Launch Mission button, so it stays legible over the Overview background.)
- **Click/accept:** opens the tab through the tab strip (`TabStrip.select_target`), so the active-tab highlight, room mount and the Loadout transition behave exactly like a side-panel click. The Castle does nothing on click.
- **Upgrade feedback:** scores refresh whenever the Overview becomes visible and on the progress events below. A building whose tier rose since the last refresh plays a scale pop (skipped under reduce-motion) and the `structure_upgraded`-family sound is NOT emitted (no new EventBus signals; the pop is visual only).
- Refresh triggers: `slot_expansion_completed`, `recipe_discovered`, `creature_acquired`, `creature_bred`, `creature_sacrificed`, `tech_unlocked`, `sanctuary_structure_built`, `item_rune_imbued`, `hero_equipment_crafted`, `skill_tree_node_unlocked`, `tarot_deck_changed`, plus visibility.

## 5. Art (Codex)

35 images: 7 buildings x 5 tiers, matching the existing diorama art style (the habitat/watchtower sprites), transparent background, same camera angle, each tier visibly grander than the last (tier 1 humble wood/stone, tier 5 grand with banners/gold trim). Queued as one row per building in `production/art-overhaul-status.md` with prompts in `design/art/sanctuary-town-buildings-prompts.md`. Claude Code processes the drops into `assets/art/sanctuary/town/<building>_tier_<n>.png` and fills the resource texture slots. The visual direction is not locked (art-overhaul §1), so these are not final art.

**Overview background (added 2026-10-07):** an opaque Codex-generated town ground plane (`assets/art/sanctuary/town/overview_background.png`, prompt in the prompts doc §4) drawn as `Diorama/Background` behind `World`, so it shows on the Overview only. Buildings must stand on its open grass: the bottom stone wall curves through the lower-left and centre, which is why the Keep moved from (450,600) to (650,585). Check any future layout change against the background, not just against other buildings.

## 6. Edge Cases

- Totals of 0 (e.g. no recipes exist yet) make that term 0, not NaN.
- A save with lots of progress shows high tiers on first view without pops (pops only fire for rises seen during the session).
- Reduce-motion: no pop; tiers still change.

## 7. Acceptance Criteria

1. Seven buildings render in the Overview at their data positions; the old Castle text placeholder is gone; existing structure rendering and its tests are unchanged.
2. Each building's tier follows `SanctuaryProgress` and the tier formula; a fresh profile shows tier 1 everywhere.
3. Clicking (or accepting a focused) building opens its tab with the tab strip highlight updated; Seer's Tower starts the Loadout transition; the Castle does nothing.
4. Hover/focus shows the info line; gamepad can reach every building.
5. Placeholders grow visibly with tier; a real texture in a tier slot replaces the placeholder with no code change.
6. Raising a tab's progress during the session pops that building on the next refresh.
